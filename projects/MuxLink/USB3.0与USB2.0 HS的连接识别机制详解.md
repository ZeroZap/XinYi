CH32H417作为同时支持USB3.0和USB2.0 HS的芯片，其连接识别机制是硬件自动完成的，对固件透明。以下是完整的识别流程：

### 1. USB3.0 vs USB2.0 HS 识别机制对比

| 识别阶段       | USB3.0 超速（5Gbps）         | USB2.0 高速（480Mbps）                  |
| :------------- | :--------------------------- | :-------------------------------------- |
| **物理层检测** | 专用差分对：SSTX±/SSRX±      | 传统D+/D-线                             |
| **初始连接**   | 设备默认处于USB2.0模式       | 以全速模式（12Mbps）连接，D+线上拉1.5kΩ |
| **握手信号**   | LFPS（低频率周期性信号）     | Chirp K/J序列                           |
| **协商过程**   | Link Training（LTSSM状态机） | 高速检测握手协议                        |
| **成功条件**   | LFPS响应 + 链路训练成功      | 设备发送Chirp K，主机回复Chirp K/J对    |
| **失败降级**   | 自动回退到USB2.0 HS模式      | 自动回退到USB2.0 FS模式                 |

### 2. USB3.0 完整识别流程（5阶段）

根据USB规范，USB3.0设备识别分为5个阶段：

#### 🧭 阶段1：物理连接检测

- 主机监测端口电气状态（VBUS电压、Rx信号线电平变化）
- 设备插入后默认处于USB2.0模式，等待主机发起SuperSpeed握手

#### ⚙️ 阶段2：链路初始化（Link Training）

这是USB3.0独有的关键步骤：

1. **LFPS（低频率周期性信号）初始化**：主机通过发送LFPS信号启动SuperSpeed握手，设备响应LFPS
2. **LTSSM状态迁移**：两端从`Rx.Detect` → `Polling` → `U0`（Active State）
3. **信号完整性确认**：完成信道均衡（equalization）

#### 🔄 阶段3：USB协议层初始化（USB Reset）

- 主机对端口进行Reset操作
- 设备进入初始状态，分配默认地址0

#### 📦 阶段4：描述符交换

主机通过地址0请求描述符，关键点在于：

- **设备描述符**：`bcdUSB`必须设为`0x0300`表示支持USB3.0
- **BOS描述符**：包含SuperSpeed能力描述，确认是否支持USB3.0功能

#### 🧩 阶段5：驱动加载与配置

主机根据VID/PID加载对应驱动，通过`SET_CONFIGURATION`设置设备配置

### 3. USB2.0 HS 识别机制（详细过程）

对于USB2.0高速模式，识别过程完全在传统的D+/D-线上完成：

#### 3.1 初始状态

- 高速设备初始以**全速设备身份出现**：D+线上有一个1.5kΩ的上拉电阻
- 主机检测到D+被拉高，认为是一个全速设备插入

#### 3.2 复位与握手

1. **主机复位**：主机驱动数据线到SE0（D+和D-全低），持续至少10ms
2. **设备Chirp K**：设备检测到SE0后，向D-线灌17.78mA电流，产生约800mV的Chirp K信号，持续1-7ms
3. **主机Chirp KJ**：若主机支持高速，在设备Chirp K结束后100μs内，回复连续的KJKJ...序列，每个K/J持续40-60μs
4. **切换高速模式**：设备检测到至少3对KJ后，断开1.5kΩ上拉，连接45Ω高速终端电阻，信号幅值降至400mV

### 4. CH32H417的硬件自动处理

CH32H417内置的USB3.0 PHY和USB2.0 HS PHY完全符合上述规范，对固件开发者来说：

| 处理项           | 说明                                                         |
| :--------------- | :----------------------------------------------------------- |
| **硬件自动协商** | Link Training和高速握手由PHY硬件完成，无需固件干预           |
| **状态指示**     | 固件可通过读取`USBHSD->MIS_ST`寄存器判断当前速度（`USBHS_UDMS_HS_MOD`位） |
| **描述符准备**   | 固件需准备BOS描述符，并在设备描述符中设置`bcdUSB=0x0300`     |
| **降级透明**     | 若连接USB2.0端口，硬件自动降级，固件无需特殊处理             |

## USB2.0与USB3.0的接收缓存配置机制

您这个问题非常专业，涉及USB复合设备在混合速度环境下的核心实现细节。答案是：**确实需要为不同速度模式准备不同的接收缓存，但并非完全独立的两套，而是通过描述符和缓冲区大小适配来实现**。

### 1. USB描述符的多速度配置机制

根据USB规范，一个设备可以支持多种速度模式，通过提供**不同的配置描述符**来实现。CH32H417的官方EVT例程中已经体现了这一点：

c

```
/* Configuration Descriptor (FS) */
const uint8_t MyCfgDescr_FS[ ] = { /* 全速模式描述符 */ };

/* Configuration Descriptor (HS) */
const uint8_t MyCfgDescr_HS[ ] = { /* 高速模式描述符 */ };
```



当设备连接时，主机通过查询设备描述符中的`bcdUSB`字段（设为0x0300表示支持USB3.0）和BOS描述符，确定设备的能力。然后根据实际连接速度，请求对应的配置描述符。

### 2. 关键差异：端点最大包长

不同速度模式下，**端点最大包长（Max Packet Size）**有显著差异：

| 速度模式           | 批量端点最大包长 | 中断端点最大包长 | 控制端点最大包长 |
| :----------------- | :--------------- | :--------------- | :--------------- |
| USB 3.0 SuperSpeed | 1024字节         | 1024字节         | 512字节          |
| USB 2.0 High-Speed | 512字节          | 64-1024字节      | 64字节           |
| USB 2.0 Full-Speed | 64字节           | 64字节           | 64字节           |

这意味着在USB3.0模式下，单次传输的数据量可以是HS模式的两倍，是FS模式的16倍。因此，**接收缓冲区必须根据当前速度模式动态适配**。

### 3. CH32H417的实现方式

从CH32H417的实测数据来看，USB3.0单端点批量传输可达**450MB/s**，这要求：

- 缓冲区大小必须足够大，避免频繁中断
- DMA缓冲区通常设置为最大包长的整数倍

官方EVT中的典型做法是：

c

```
// 端点缓冲区定义（示例）
__attribute__((aligned(4))) uint8_t USBHS_EP0_Buf[DEF_USBD_UEP0_SIZE];
__attribute__((aligned(4))) uint8_t USBHS_EP2_Tx_Buf[DEF_USB_EP2_HS_SIZE];
__attribute__((aligned(4))) uint8_t USBHS_EP2_Rx_Buf[DEF_USB_EP2_HS_SIZE];

// 其中 DEF_USB_EP2_HS_SIZE 在不同速度模式下被定义为不同的值
#ifdef USB_HS_MODE
    #define DEF_USB_EP2_HS_SIZE  512
#else
    #define DEF_USB_EP2_HS_SIZE  64
#endif
```



### 4. 在MuxLink中的应用

结合我们之前确定的16端点配置表，您需要为每个端点准备不同速度模式的描述符版本，但**可以共享相同的物理缓冲区**，只需确保缓冲区大小能满足最高速度模式（USB3.0）的需求。

| EP4-5   | CDC1数据  | 1024字节         | 512字节             | **1024字节** |

| EP7-8   | CDC2数据  | 1024字节         | 512字节             | **1024字节** |

### 5. 固件实现要点

在初始化时，根据当前检测到的速度模式选择合适的描述符和端点配置：

c

```
void USBHS_Device_Endp_Init(void)
{
    if (USBHS_DevSpeed == USBHS_SPEED_HIGH) {
        // HS模式：批量端点512字节，中断端点64字节
        USBHSD->UEP2_MAX_LEN = DEF_USB_EP2_HS_SIZE;  // 512
        USBHSD->UEP6_MAX_LEN = 64;  // 中断端点
    } else if (USBHS_DevSpeed == USBHS_SPEED_SUPER) {
        // USB3.0模式：所有端点最大包长1024字节
        USBHSD->UEP2_MAX_LEN = 1024;
        USBHSD->UEP6_MAX_LEN = 1024;
    }
    
    // DMA缓冲区地址设置
    USBHSD->UEP2_RX_DMA = (uint32_t)USBHS_EP2_Rx_Buf;
    USBHSD->UEP2_TX_DMA = (uint32_t)USBHS_EP2_Tx_Buf;
    // ...
}
```



### 6. 自动速度检测机制

CH32H417的硬件会自动处理速度协商：

- 连接USB3.0端口时，通过LFPS握手进入SuperSpeed模式
- 连接USB2.0 HS端口时，通过Chirp K/J序列进入高速模式
- 固件通过读取`USBHSD->MIS_ST`寄存器的`USBHS_UDMS_HS_MOD`位判断当前速度
